## Changes and source behavior

- `generation/coordinator.py`: only `request.is_fallback` handles a typed unavailable/incomplete channel or explicitly classified provider-output error by emitting configured fixed text and invoking the existing successful final committer. Existing failed attempts, usage and UNKNOWN remain. No second claim, provider retry, refund or new model send. The frozen P5 router/upgrade switches are unchanged.
- Classification uses exact ProviderError type plus explicit codes; HTTP errors require one of 400/404/409/422/429/500/502/503. Transport/response-invalid/stream-failed/no-response codes are named explicitly. Internal channel failures have a separate type. ModelCallTimeout, cancellation, deadline, all gate/identity/settlement errors, HTTP401/403, ambiguous PROVIDER_API_ERROR bodies and unknown exceptions remain fatal; no substring-based conversion to success. An unclassified status or error remains failed rather than guessed safe.
- `models/stream.py`: final bookkeeping carries `provider_answer_done` so fallback can distinguish the adapter's synthetic EOF Done from actual answer completion. fail() preserves structured HTTP status for classification. Normal generation still follows the prior EOF behavior, verified by its affected tests.
- `generation/types.py`, `service.py`: configured fallback response is retained for a failed model attempt; the non-vision image label is now exactly Go's `[用户上传图片内容]`.
- Fallback ignores thinking events, as consumeFallbackStream processes answer events only. Non-fallback thinking and error behavior is unchanged.

Fixed source: `session_knowledge_qa.go` handleModelFallback, consumeFallbackStream, emitFallbackAnswer, renderFallbackPrompt; `internal/handler/session/qa.go` normal completion handler appends `data.Content` before completing on Done.

**Partial EOF semantics:** source emits `partial ` with Done=false, then configured fixed reply with Done=true. The HTTP completion handler appends both, so stored answer is `partial FIXED_SOURCE_REPLY`, without replacing the partial or inserting a separator. Cheap/DYNAMIC retains its approved buffering; on fallback completion the same answer fragments are emitted in source order. This comparison does not claim identical timing while Cheap is buffered. A decoder tail is not flushed on incomplete fallback EOF. Existing P5 truncation/empty/invalid-handle upgrades for completed model answers remain unchanged.
