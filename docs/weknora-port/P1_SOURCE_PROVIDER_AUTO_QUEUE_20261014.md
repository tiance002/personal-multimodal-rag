Same provider/model/URL with different source produces different immutable IDs/physical hashes. There is no schema change: existing fixed models.source/parameters columns already express this split.

Existing role JSON missing source becomes the explicit legacy-vendor/v1 representation (source=''), retaining original provider/protocol behavior. Existing physical v1 rows retain original source strings, ID, identity and physical hashes. Loader recognizes v2 only if its complete pinned identity matches; otherwise reconstructs the exact old v1 identity and verifies all existing checks. In particular an old vendor literally named remote remains legacy when its v1 hash says so. No vendor/URL classification. Existing v1 credential-only update keeps ID. No batch migration of existing candidate rows or old business DB.

Source change participates in credential rebinding protection: changing source/provider/endpoint cannot silently inherit old credential. ModelConfig carries source independently; neutral registry and ProviderModel reject local before any factory/transport send. Unknown source is refused. Auxiliary role choices and P5 thresholds/upgrade switches unchanged.
