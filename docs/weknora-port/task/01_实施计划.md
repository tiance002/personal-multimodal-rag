## 1. 一句话边界

**WeKnora 的文档解析、索引、检索、问题理解、上下文、短期历史、长期记忆、模型协议、SSE、引用、普通问答和失败处理，按指定提交的实际源码行为移植；仅保留两项自研决策逻辑进入正式问答主链：① P5 Cheap/Expensive 动态路由；② Cheap 失败后受控升级 Expensive。**

独立保留六个公开数据集的评测中心（不改变产品主链）。基于用户已讨论确认的例外，隐私外发同意、必要费用边界、供应商请求幂等和不确定用量保护可以作为**最小工程安全封装**存在，不得再成为自定义 RAG 算法、模型参数或输出策略。每个例外需要写明“上游缺失什么、为什么保留、代价、验证证据”；不得将 V4 临时任务限制误当产品机制。

**不做的事：**不引入新的在线语义 Judge、原有 Regex 强校验、定制关键词检索路由、按问题关键词分配 1024/2048/4096 Token、打满输出额度才能上线的探针、不必要的 Provider 重试变体；不把 WeKnora 所有无关产品（IM 集成、企业租户全套、沙箱等）误当本轮必须复刻的目标。已有 Smart/Agent 产品入口必须明确其去向，不能悄悄删除；若超出本轮 RAG 核心，请单独列为后续阶段并保留可理解提示。

## 2. 主链架构与准确插入点

```text
输入/会话/授权
   ↓
WeKnora Python: 历史读取 + Query Understand（启用条件按上游）
   ↓
WeKnora Python: Rewrite / Expansion → KB/关键词/向量候选
   ↓
WeKnora Python: Weighted RRF → Rerank → Merge/Parent/邻居 → Filter TopK
   ↓
WeKnora Python: Context / prompt / Memory 组合（完成同一份证据上下文）
   ↓
【自研 1】P5 Router：Q0/问题特征/输入负载 → Cheap 或 Expensive
   ↓
WeKnora Python: 统一 Provider/ChatStream（按选中模型 vendor compat 渲染）
   ↓
【自研 2】Cheap 升级判定：仅在可信、已定义的失败信号触发，最多升级一次
   ├─ Cheap 合格 → WeKnora 答案与来源呈现
   └─ 允许升级 → 用同一份证据上下文调用 Expensive → WeKnora 呈现
   ↓
WeKnora Python: 事件、会话历史、SSE 恢复、用户可见引用
   ↓
React 前端；评测侧记录路由质量/费用/延迟（只旁路观测）
```

**注意：**WeKnora `session_knowledge_qa.go` 的插件流水线在不同请求条件下有分支。图是业务层级，不得强制所有问答都执行 Rerank、Rewrite、Memory；真正的条件与顺序以固定源码为准。特别是 `FILTER_TOP_K` 在 `CHUNK_MERGE` **之后**；`EnableQueryExpansion` 不是“只要无候选就自动扩展”，须按 `search.go` 实际条件执行。

**动态路由只能决定最终 Chat/ChatStream 的模型选择**，不得擅自改变先前的检索、查询改写模型、Embedding、Rerank、Memory 提取模型。改写等辅助模型按 WeKnora 的独立配置和调用流程执行，其 Token 与费用必须计入评测的总成本，防止虚高“路由节省”。同一用户问题 Cheap→Expensive 必须复用同一份已准备上下文，不重新检索，也不无授权重发旧供应商请求。

## 5. 动态路由与 Cheap 失败升级的冻结细节

**保留原版 P5 决策函数的可观察结果，不以“移植”为名重设参数：**`rule_router_v1.py` 的 `threshold=0.35`、六项特征 `T/C/J/D/L/M`、`score = sum(contributions) / 100`、初始 Cheap/Expensive 模型角色。`router_feature_extraction.py` 的输入负载以前在普通 `bootstrap.py` 装配未传 estimator，须在新接口接入有来源的真实估算器；未知值仍标 `UNKNOWN`，不得冒充 0 或新增一轮 LLM 来分类。

**保留升级“能力”，但拆开信号与策略：**

| 触发 | 初始策略 | 原因 |
|---|---|---|
| Cheap 正常 `stop`、有效非空答复、引用句柄正确 | 不升级 | 上游正常成功路径 |
| Cheap `length`/max token 截断 | 允许升级；保持历史普通服务已启用规则 | 明确、非语义推测信号 |
| Cheap 空答复、明确无效引用句柄 | 允许升级 | 直接可观测的基础失败 |
| Cheap 只有整句明确拒答 | 维持旧配置默认 **关闭**，可单独评测 | 不能把资料不足等于一定要换贵模型 |
| Cheap HTTP/网络/服务超时 | 维持历史 `provider_fallback=false`，**不自动升级**；如果你要改成开启，需另行明确授权 | 超时可能已经发送并计费；先不在迁移中偷改 |
| Cheap 未授权、KB 外发不同意、费用门拒绝、scope/Run 失效 | **禁止升级** | 这是安全/业务准入，不是质量低 |
| 旧 Validator 的 `UNSUPPORTED_ANSWER`、正则数值/单位/结构化事实误拒 | **不迁移到新在线升级触发** | 已决定其余行为对齐 WeKnora，严格语义规则移离主链 |

**只允许 Cheap→Expensive，最多额外一次。**第一跳已选 Expensive 时不再升级。Cheap 若需完整判定后才知道是否升级，则在“路由层”内暂存其候选片段；不得把已判定失败的 Cheap 部分答复作为正式历史答案。Expensive 或最终认可的答复仍按 WeKnora SSE/引用语义发布。这一点是动态路由唯一不可避免的输出协调差异，必须在 `ACCEPTED_DEVIATIONS.md` 说明其实时打字效果与延迟代价。

建议记录初始评分、特征贡献、估算来源、最终角色、Cheap 失败信号、升级原因、两次耗时与 Token；不读取/记录私有内容作为默认追踪字段。

## 6. 必须按“区别”处理的安全与旧数据

- **最小保留：**WeKnora 权限/API Key 加密/作用域/基本用量统计优先对等移植。若上游无逐 KB 云端外发同意、月度费用硬限额、供应商 request_id 持久幂等或 UNKNOWN 预留，允许保留独立安全封装；禁止它决定 Chunk/Rerank/Prompt/输出长度或动态评分。
- **临时实验退出产品：**旧 V4/G4 TaskFence、7 次探针、7 次网页请求上限、打满输出 Token 的强制合格证明、旧 V6 专项 Grant，只作历史审计材料/离线旧合同，不接入新正式启动入口。
- **不能删除的历史：**原始文件、索引版本、业务数据库和卷、Run/Attempt/引用、已结算/UNKNOWN 费用记录、冻结 Gold/公开数据集、旧报告与授权文件。
- **旧项目与新项目隔离：**新实现建议单独工作树/目录、独立数据库/存储/Redis 前缀和版本配置；业务数据在正式切换批准前只读快照/映射，无写入旧库。非源码兼容的历史只以归档回读，不混入新模型上下文。
- **存储语义：**上游 PG 的关键词检索可能依赖 ParadeDB，旧项目的自建 BM25 `chunk_terms` **不能未经对照就称为等价**。选择上游相同引擎，或者以针对同一 fixture 的排序/阈值证明替代适配，并明示不能完全等价之处；不在旧 DB 上随意安装扩展。

## 7. 判定 PASS 的规则

1. **实现证据：**固定 SHA 已核查，上游具体函数/参数/分支已经读取；Python 行为对照有输入、期望和实际结果。
2. **区分层级：**`SOURCE_READ`、`IMPLEMENTED`、`OFFLINE_PASS`、`ISOLATED_INTEGRATION_PASS`、`REAL_PROVIDER_PASS`、`CUTOVER_PASS`，不能靠一项泛称“全部通过”。
3. **足够覆盖：**优先针对真实差异和常见分支的小型 Golden Fixture；真实模型随机生成的正文不要求逐字一致。对源格式、检索 ID/分数、配置生效、HTTP wire、SSE 事件顺序和故障终态应做确定性对照。
4. **成本保护：**无批准不发真实收费 API，不重试旧未知 Run；旧 UNKNOWN 不释放不迁移成 0，现有 31 项旧分层违规不报成全局通过。
5. **不自欺：**无法让 WeKnora 同配置执行的项目记录 `PARITY_BLOCKED`，不能改 fixture 造 PASS；如果真实网络/提供商本身失败，区分上游 parity 与线上可用性。
6. **分离清理：**新链可见功能及影子数据通过后，才在单独 commit 删除旧主链；删除前需确认没有主产品调用方，历史审计文件仍保留。

## 8. 验收最终状态

交付的是一个**Python WeKnora-RAG 主链 + 正式 P5 Cheap/Expensive 路由和升级 + React + 六数据集评测**。在 `WEKNORA_BASELINE`（不调用自研路由）模式下，对可确定行为可与固定 WeKnora 对照；在 `DYNAMIC` 模式下只有模型选择、允许的 Cheap 失败升级及其流式协调发生差异。所有例外均登记，不允许逐次调试再增加未经批准的第三套问答规则。
