- **DOCX MarkItDown and full DocxParser fallback routes: PASS for the synthetic fixture.** The test directly executes fixed-source `StdMarkitdownParser` plus fixed-source `MarkdownTableFormatter` and `MarkdownImageBase64`; normalized Markdown and decoded image bytes match the port. The 120-row fixture checks heading/table order, escaped cell delimiters, and embedded image retention. When MarkItDown fails or returns empty, the port now executes the fully attributed upstream `DocxParser.parse_into_text` implementation, retaining page mapping, multiprocessing, body-order composition, image processing and its simple-method error fallback. The test observes `_execute_multiprocess_tasks` to prove that the process-pool path is entered, then compares content and image bytes with a direct call to the same fixed-source parser.
- **Excel and MarkItDown routing: PASS for tested synthetic cases.** XLSX output with duplicate headers, blank rows, multiple sheets, and `_xlfn.DISPIMG(...)` filtering matches direct execution of fixed-source `ExcelParser`; unrelated format-normalization helpers are stubbed to identity for this valid XLSX fixture. CSV and a generated one-slide PPTX match fixed-source `StdMarkitdownParser` followed by the actual fixed-source Markdown formatting/image extraction classes. `.xls`, `.ppt`, and other MarkItDown formats are not parity-tested.
- **Markdown and standalone images: structural behavior tested.** Markdown table normalization and base64 image extraction are adapted from upstream Markdown helpers; data-image output is compared through DOCX and CSV source wrappers. Standalone images are preserved as assets.
- **OCR/VLM: NOT RUN.** Scanned pages and standalone images remain assets; `ocr_status` says `NOT_RUN`. No text is fabricated and no provider/model call was made.

Full upstream MIT terms are in `LICENSE-THIRD-PARTY-WeKnora-MIT.txt`.
- `backend/weknora_port/ingestion/core.py` owns extension/engine dispatch, metadata/failure boundaries, parser configuration, chunk calls, and storage-neutral records. Explicit parser overrides resolve tenant then upload values. Chunk config resolves KB, process, then upload overrides; absent or zero sizes do not erase previous values, while explicit booleans do.
- Fixed Go chunker sources are copied unchanged under ignored `var/weknora-port/oracle/chunker/` by `scripts/weknora_port_chunker_oracle.py`, then executed as a test oracle. The Go test tooling is outside the Python application namespace. `execution_report.json` and `execution.log` record oracle provenance/results; generated source copies and reports are ignored local evidence.

The application dependency manifest is outside this task's ownership; root should integrate applicable pins from `backend/weknora_port/ingestion/requirements-parser-parity.txt` before runtime use.
