# ECS 增量部署

让本地已验证的合法变更进入正确 ECS 应用服务，并证明运行身份、数据保护和回滚入口。历史快照是线索，不是当前服务器状态；本 Skill 不产生部署或模型调用授权。

## 1. 先确定最小范围

读取项目 `AGENTS.md`、`AGENTS.override.md` 和当前任务相关进度；核对实际 HEAD、dirty 路径、目标提交及已有验证。已证明同源码/配置的定向验证直接复用，相关输入变化才补测。

多任务共享目录时先确认分支和写入归属；暂存、提交或打包前重新核对冻结的branch/HEAD。若并行任务已切换分支或增加合法改动，保留该目录，转到独立worktree继续自己的提交；不切回、reset、stash或把其他任务的文件纳入发布。

部署时先读 [deployment-runbook.md](references/deployment-runbook.md) 的身份/差异与阶段表。只读确认主机、Compose 项目及**全部有效配置文件**、API/Worker 的镜像与挂载、PG物理身份、Redis DB/前缀、存储和旧版本，再形成：

`目标提交 → 变更文件 → 受影响服务/合同 → 验证 → 镜像与配置回滚材料`。

API/Worker共享镜像不等于必须同时更新：检查共同模块、任务合同和各自运行状态。前端、数据库、索引未变化就不构建/重启；原本停着的Worker不因发布自动启动。

🔴 **STOP**：目标身份、合法变更或旧版本无法核实，先停变更；涉及Schema/数据转换/索引重建/不可逆操作，提交必要性、影响和独立恢复方案，请Owner批准。不得用应用更新授权代替这些授权。

## 2. 固定发布顺序

1. **定向测试**：复用当前目标版本已有证据；实际失败先定位本地问题，不上传试错。
2. **构建**：只构建受影响镜像；核对linux/amd64、实际包版本、源码manifest、正式模块导入及镜像内凭据/临时资产排除。进程exit0也要检查语义status。
3. **传输**：不可变归档校验大小/SHA；失败部分文件保留并标不可用。只有基础镜像/依赖一致已证明时才采用文件manifest+离线增量构建，记录不同的本机/远端Image ID。
4. **暂存/切换**：保存旧镜像及配置原字节/SHA；比较有效Compose，授权范围内每次只更新目标应用服务；确认无在途发送/任务，不重置旧UNKNOWN。使用runbook中的已核实入口，禁止复制旧任务授权。
5. **运行核验**：检查容器实际Image ID、OCI revision、模块`__file__`/SHA及遮蔽挂载；标签相同或healthy不代表新代码已加载。
6. **验收**：正式鉴权Ready、API/Worker合同及本次改动涉及的来源/索引/历史检查；需要真实问答时先核对独立有效Provider授权。零云验收和真实问答分别报告，不为验收自动开启云开关。

每步保留命令、退出码、语义结果和下一分支；一次失败后先用新证据修正假设，不重复盲重启。身份错误、数据异常或新的Provider UNKNOWN停止相关发送，保留原件并只读对账。

## 3. 按故障层次分支

| 触发条件 | 首查/判据 | 首选动作 → 仍失败 |
|---|---|---|
| 构建失败或包/架构不同 | 构建日志、平台、源码/依赖差异 | 修构建输入；未证明兼容则不切换 |
| SSH/传输失败 | 退出码、主机固定身份、远端大小/SHA | 保留部分文件；已核实底座才选增量构建；身份/散列不符STOP |
| 配置/启动失败 | 同一Compose文件链的config、日志、实际命令与挂载 | 修已定位配置；只回滚受影响应用/配置，不动PG/Redis |
| healthy但旧代码/API与Worker不一致 | Image ID→revision→实际加载路径/SHA→任务合同 | 区分旧标签、旧容器或源码覆盖；修对应映射，不重建整栈 |
| PG/Redis身份或数量不符 | 当前物理身份、版本/启用状态及本次before快照 | 先解释批准过的来源变更；无法解释则STOP，不能调期望值凑PASS |
| API/SSE工具报错 | 原request_id的协议终态、PG/历史、Provider账本 | 只读恢复已完成操作；UNKNOWN不重发，不把工具错算模型错 |

出现匹配症状时按ID读取 [incident-log.md](references/incident-log.md)，先核前提与证据等级；更多故障类别和准确命令见runbook。历史中的certifi版本、计数、镜像及目录都不是未来的固定目标。

## 4. 验收与回滚

只在目标运行版本、受影响服务/合同、数据与索引保护、本次业务验收和可用回滚证据均满足时报告该范围PASS。未获模型许可时写`REAL_QA_NOT_RUN`；缺指标写`NOT_RECORDED`，不能把上限/单次采样当峰值。

故障时区分**应用镜像回滚、配置回滚、Git代码回退、数据库恢复**。应用回滚沿已验证旧镜像与原配置，仅重建受影响服务；有数据变更时旧镜像不替代数据库恢复。回滚后重新核验运行版本和身份。具体步骤见runbook回滚节。

禁止把`git reset --hard`、覆盖用户dirty文件、`down -v`、prune、删卷/数据库或重Embedding当默认排障；不改变模型、Prompt、Rerank、租户或生产云开关来制造发布PASS。

## 5. 故障解决后再进化

先恢复用户任务，再将已验证的新事件按故障库字段登记；已有规则正确就只补案例，不扩主文件。未解决原因标PARTIAL/UNKNOWN；凭据只留变量名/文件引用，原日志先脱敏。

需要改规则时读取 [evolution.md](references/evolution.md)，应用已安装 `darwin-skill` 的测试Prompt、独立行为对照和3名同-judge配对多数评估。每轮一个因素，有行为收益且无新增风险才保留；不要用一次自评分或单纯篇幅增加证明收益。

🔴 **CHECKPOINT**：新增部署权限、数据操作或重要规则变化须Owner审查；循环不自动开新Goal/云调用。不改全局Skills、不自动Push。每次交付：范围/版本、实际命令结果、证据、遗留、回滚状态和本地提交。
