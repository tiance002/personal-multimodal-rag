# Retrieval reference adaptation for V1

**Purpose:** record the WeKnora and RAGFlow retrieval patterns considered for the local-first RAG profile. This is a reference comparison with a bounded-sanity checkpoint, not a release or real-material acceptance claim.

**Pinned references:** WeKnora [`v0.8.2`](https://github.com/Tencent/WeKnora/releases/tag/v0.8.2) and RAGFlow [`v0.27.2`](https://github.com/infiniflow/ragflow/releases/tag/v0.27.2). RAGFlow `v1.0.0-rc1` describes a Go rewrite; the RAGFlow findings below apply only to the tagged Python retrieval path and must not be carried over to that rewrite without a separate audit.

**Current Project column:** historical audit snapshot [`rag-current-state.md`](rag-current-state.md), source `0f73521`. Treat those comparison facts as “as of the audit snapshot,” not as a description of the later implementation checkpoint below.

|---|---|---|---|---|
| Retrieval modes and routing | **CURRENT_PROJECT:** Quick and Smart share `KnowledgeGateway`; product retrieval currently uses the configured hybrid retriever, with no product selector for vector-only or keyword-only retrieval. Keyword scoring is term frequency plus an exact-query bonus, not BM25. [`rag-current-state.md`](rag-current-state.md) | **REFERENCE_ARCHITECTURE:** Agent `search_knowledge` defaults to `hybrid` (vector + keyword), with `semantic` vector-only and `keyword` backend search modes. It documents per-KB capability fallback. [Agent guide](https://github.com/Tencent/WeKnora/blob/v0.8.2/website-docs/03-features/07-agent.md) | **REFERENCE_ARCHITECTURE:** the inspected Agent tool uses weighted hybrid retrieval; this tool path does not evidence a separate semantic/keyword mode selector. | Fusion equation and weights | **CURRENT_PROJECT:** current product fusion is equal-weight RRF with `k=60`: `S(d)=Σc 1/(60+r_c(d))`. It preserves raw channel scores separately; those scores are not blended. [Fusion implementation](../../backend/app/domain/fusion.py) | **REFERENCE_ARCHITECTURE / REFERENCE_DEFAULT:** weighted RRF uses 1-based rank within each channel: `S(d)=w_v/(k+r_v(d)) + w_kw/(k+r_kw(d))`, including only channels containing the item. Default `k=60`, vector weight `.7`, keyword weight `.3`; custom positive weights are used as given, so explicit `.5/.5` is supported. These are rank-vote weights, not raw-score weights. [Fusion implementation](https://github.com/Tencent/WeKnora/blob/v0.8.2/internal/application/service/knowledgebase_search_fusion.go) · [Config defaults](https://github.com/Tencent/WeKnora/blob/v0.8.2/internal/types/retrieval_config.go) | **REFERENCE_ARCHITECTURE / REFERENCE_DEFAULT:** the Python core blends `term_weight × token_similarity + vector_weight × cosine_similarity + rank_feature`, with `term_weight=1−vector_weight`; core defaults to term `.7` / vector `.3`. A configured reranker supplies the vector-side score instead. The Agent default keyword weight `.5` maps to vector weight `.5`. This is weighted similarity, **not RRF**. [Core search](https://github.com/infiniflow/ragflow/blob/v0.27.2/rag/nlp/search.py) · [Agent tool](https://github.com/infiniflow/ragflow/blob/v0.27.2/agent/tools/retrieval.py) | **PROJECT_ADAPTATION:** use rank-weighted RRF with `k=60`, vector `.7`, keyword `.3`, following WeKnora’s documented rank weighting. Do not reinterpret RAGFlow’s raw similarity weights as RRF weights. |
| Score thresholds and meaning | **CURRENT_PROJECT:** vector similarity, keyword term-count scores and fused ranks have different meanings; current source does not establish a common threshold calibration. | **REFERENCE_DEFAULT:** WeKnora global conversation config lists vector `.2` and keyword `.3` thresholds; CLI docs define channel thresholds as pre-fusion filters. Its fused rank score is not a vector-similarity confidence. [Agent guide](https://github.com/Tencent/WeKnora/blob/v0.8.2/website-docs/03-features/07-agent.md) · [Config](https://github.com/Tencent/WeKnora/blob/v0.8.2/config/config.yaml) · [CLI search contract](https://github.com/Tencent/WeKnora/blob/v0.8.2/cli/skills/weknora-rag-search/references/search-chunks.md) | **REFERENCE_DEFAULT:** core threshold defaults to `.2` on its blended similarity path; docs illustrate scores on a 0–100 presentation scale. These semantics are not equivalent to WeKnora RRF or the project’s channel scores. [Core search](https://github.com/infiniflow/ragflow/blob/v0.27.2/rag/nlp/search.py) · [Retrieval FAQ](https://github.com/infiniflow/ragflow/blob/v0.27.2/docs/guides/dataset/notes_and_faqs.md) | **PROJECT_ADAPTATION:** copy no external threshold values. Validate any project threshold against the project’s own retrieval judgments and score semantics before enabling it. |

[Agent guide](https://github.com/Tencent/WeKnora/blob/v0.8.2/website-docs/03-features/07-agent.md) · [Config](https://github.com/Tencent/WeKnora/blob/v0.8.2/config/config.yaml) | **REFERENCE_DEFAULT:** core rerank candidate window defaults to 64, ANN `knn_top_k=1024`, and `knn_num_candidates=2048`; Agent `top_n=8` and `top_k=1024`. These are not interchangeable result limits. [Core search](https://github.com/infiniflow/ragflow/blob/v0.27.2/rag/nlp/search.py) · [Agent tool](https://github.com/infiniflow/ragflow/blob/v0.27.2/agent/tools/retrieval.py) | **PROJECT_ADAPTATION:** retain `candidate_k=32` (an explicit project choice, not either reference default), final `top_k=5`, and the existing 8,000-character context budget. Keep candidate retrieval, final results and context selection as separate budgets. Characters are not tokens. |
| Reranking and diversity | **CURRENT_PROJECT:** no reranker or MMR is wired in production. Context selection is stable and character-budget based. [`rag-current-state.md`](rag-current-state.md) | **REFERENCE_ARCHITECTURE / REFERENCE_DEFAULT:** reranking is optional; documented API behavior then applies threshold/fallback rules and MMR with `λ=.7`. [API overview](https://github.com/Tencent/WeKnora/blob/v0.8.2/website-docs/04-api/01-api-overview.md) | **REFERENCE_ARCHITECTURE:** a reranker is optional in the core path. No MMR step was evidenced in the inspected core or Agent retrieval path. [Core search](https://github.com/infiniflow/ragflow/blob/v0.27.2/rag/nlp/search.py) · [Agent tool](https://github.com/infiniflow/ragflow/blob/v0.27.2/agent/tools/retrieval.py) | **PROJECT_ADAPTATION:** keep ranking and diversity ports optional and default-off. ## Implementation checkpoint

At implementation commit `0b68385f237e9560ef6929297d459973a4def89d`, the product wiring uses adaptive retrieval: semantic vector by default, conditional exact/identifier hybrid routing, weighted RRF (`k=60`, vector `.7`, keyword `.3`), `top_k=5`, `candidate_k=32`, and an 8,000-character context budget. The historical `0f73521` comparison above is unchanged.

Validation recorded for this checkpoint: 44 scoped tests, exit 0; the bounded reference run completed with exit 0, 48 retrieval calls, 24 query-embedding calls, zero database writes, and zero LLM calls. Its bounded sanity Gate is **PASS**. See [V1 retrieval decision](../decisions/v1-retrieval-decision.md) for the run command, scope, results, and limitations.

The bounded sanity Gate PASS is not release acceptance. Real-material source-grounding and product UI acceptance remain separate and are not claimed complete here.
